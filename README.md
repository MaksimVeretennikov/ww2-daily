# Дневник Второй Мировой — ежедневная рутина

Автопостинг для Telegram-канала [@ww2_dnevnik](https://t.me/ww2_dnevnik):
каждый день — что происходило во Второй мировой ровно **85 лет назад**, с
архивной фотографией. Раньше это крутилось на make.com; теперь — как **ежедневная
облачная рутина Claude** (Opus 4.8, максимальный effort), которая работает в
облаке независимо от того, включён ли твой компьютер.

## Что делает

1. Считает целевую дату: сегодня минус 85 лет (по Москве).
2. Собирает факты из нескольких источников:
   - [onwar.com](https://www.onwar.com/) — хроника по дням;
   - [ww2db.com](https://ww2db.com/) — «today in WW2 history»;
   - [ru.wikipedia «Хроника Великой Отечественной войны»](https://ru.wikipedia.org/wiki/Хроника_Великой_Отечественной_войны)
     — по дням, упор на Восточный фронт;
   - [en.wikipedia «Timeline of World War II»](https://en.wikipedia.org/wiki/Timeline_of_World_War_II_(1941)).
3. Claude (сама сессия рутины) пишет пост, подпись к фото и короткий текст для X.
4. Ищет фото на Wikimedia Commons, отсекает уже использованные и послевоенные,
   **смотрит на кадры** и выбирает лучший.
5. Публикует в Telegram (и опционально в X), сохраняет историю в репозиторий —
   чтобы не повторялись ни темы, ни фотографии.

## Архитектура

| Часть | Где |
|---|---|
| Творчество (текст, выбор фото) | Сама сессия Claude по навыку `.claude/skills/daily-post/` |
| Сбор фактов | `scripts/fetch_sources.py` → `ww2daily/sources.py` |
| Поиск/дедуп фото | `scripts/find_photo.py` → `ww2daily/commons.py` |
| Публикация | `scripts/publish.py` → `ww2daily/telegram.py`, `ww2daily/twitter.py` |
| Память (антиповторы) | `state/history.json` (коммитится обратно) |

Внешние сервисы из make-сценария (OpenAI, Buffer, Dropbox, Cloudinary, E2B,
Airtable) больше **не нужны**: модель — это сама рутина, фото хостит Telegram,
память — в git.

## Настройка рутины (один раз)

1. Зайди на **[claude.ai/code](https://claude.ai/code)** → раздел Routines →
   **Create routine**.
2. **Repository:** выбери `maksimveretennikov/ww2-daily`.
3. **Model:** Opus 4.8. Отдельного выбора «Effort» в UI рутины нет — максимальный
   уровень рассуждений уже задан в репозитории через `.claude/settings.json`
   (`"effortLevel": "max"`), который cloud-сессия читает автоматически. Менять
   ничего не нужно.
4. **Schedule:** Daily, время по Москве (например 09:00 — поменяй на нужное;
   время вводится в твоём часовом поясе и конвертируется автоматически).
5. **Prompt рутины** — короткий, вся логика в репозитории:
   > Запусти навык `daily-post` и выпусти сегодняшний пост для канала
   > @ww2_dnevnik, строго следуя инструкции навыка. Работай автономно.
6. **Environment → Environment variables** (формат `.env`, без кавычек) —
   см. `.env.example`. Минимум:
   ```
   TELEGRAM_BOT_TOKEN=...        # бот должен быть админом канала
   TELEGRAM_CHANNEL=@ww2_dnevnik
   ```
7. **Environment → Network access → Custom.** Добавь домены (и оставь галочку
   «common package managers», чтобы ставился pip):
   ```
   api.telegram.org
   commons.wikimedia.org
   upload.wikimedia.org
   ru.wikipedia.org
   en.wikipedia.org
   www.onwar.com
   ww2db.com
   ```
   (Добавь `api.x.com` и `upload.twitter.com`, если включишь X.)
   Эти настройки лежат не на странице рутины, а в её **Cloud Environment**:
   карандаш (Edit) → под Instructions навести на окружение «Default» → шестерёнка
   → диалог **Update cloud environment**.
   **Setup script оставь пустым** — зависимости ставит сам навык первым шагом
   (`pip install -r requirements.txt`) уже внутри сессии, где рабочая папка —
   корень репозитория; из Setup script этот путь не виден.
8. **Право на push в `main`.** Рутина по умолчанию пушит только в ветки
   `claude/*`. Чтобы память (`state/history.json`) накапливалась, разреши push в
   основную ветку — либо в настройках рутины, либо принимай ежедневный PR от неё.
   Если оставляешь только `claude/*` — память будет уходить в PR, который нужно
   мёржить (менее удобно).

### Что нужно от тебя (доступы)

- **`TELEGRAM_BOT_TOKEN`** — токен бота от @BotFather (тот же бот, что постит
  сейчас). Бот должен быть **админом** `@ww2_dnevnik` с правом публикации.
- *(опционально, позже)* ключи **X API** — см. ниже.

`ANTHROPIC_API_KEY` **не нужен**: пост пишет сама сессия рутины (это и есть
Opus 4.8). OpenAI/Buffer/Dropbox/Cloudinary — тоже не нужны.

## X (Twitter) — кросс-пост утреннего поста и вечерней рубрики

В X уходит короткий английский `post_x` с фото от утреннего поста и вечерней
рубрики. **Опросы в X не идут** (Buffer/X не умеют квиз-опросы). Два способа:

### Вариант A — Buffer с фото, бесплатно (через вебхук make)
Buffer постит медиа только через старый REST API, а он требует
**зарегистрированного приложения**; регистрацию новых приложений Buffer закрыл.
У make.com приложение есть (исторически), поэтому оставляем **один крошечный
сценарий make** только под X:

1. В make создай сценарий: **`Webhook`** → **`Buffer: Create Status`**.
2. В модуле Buffer: `Text` = `{{1.text}}`, `Media → Picture/Thumbnail` =
   `{{1.image_url}}`, профиль — твой X-аккаунт, режим — «Share now».
3. Скопируй URL вебхука и положи в env рутины: `BUFFER_WEBHOOK_URL=https://hook…`.
4. Готово. Рутина после поста в Telegram шлёт на вебхук
   `{"text": post_x, "image_url": "<публичная ссылка на фото Commons>"}`.

Картинка — прямая ссылка на Wikimedia Commons (Dropbox/Cloudinary не нужны).
Если `BUFFER_WEBHOOK_URL` задан — он используется в приоритете.

### Вариант B — X API напрямую, с фото (pay-per-use ≈ $0.01/пост)
Если не хочешь держать сценарий в make: на [developer.x.com](https://developer.x.com/)
создай app (**Read and Write**), возьми 5 ключей `X_*`, поставь `X_ENABLED=1`,
раскомментируй `tweepy` в `requirements.txt`. Используется, только если
`BUFFER_WEBHOOK_URL` пуст. ~$0.30–0.60/мес за 2 поста в день.

## VK — кросспост в своё сообщество (бесплатно)

Каждый пост (утренний + вечерняя рубрика) зеркалится в **сообщество VK**, которым
ты владеешь, с фото. Постинг с картинкой требует **пользовательского** токена
(токен сообщества не умеет загружать фото на стену).

1. Создай **сообщество** (vk.com → Сообщества → Создать) — паблик/группу.
2. Узнай его **числовой ID** (`VK_GROUP_ID`): открой сообщество → в адресе
   `club123456` число и есть id; если адрес именной — Управление → в URL будет id.
3. Получи **пользовательский токен** со scope `wall,photos,groups,offline`
   (через своё Standalone-приложение на vk.com/apps?act=manage и OAuth, либо
   удобный «получатель токена»). `offline` делает токен бессрочным.
4. В окружение «WW2 Daily» добавь:
   ```
   VK_ACCESS_TOKEN=vk1.a.xxxxx
   VK_GROUP_ID=123456
   VK_FOOTER=Ежедневно в Telegram: https://t.me/ww2_dnevnik
   ```
Фото грузится напрямую из файла (прокси не нужен), HTML из подписи вычищается,
а `VK_FOOTER` (ссылка на Telegram) добавляется в конец — это воронка из VK в TG.

## Дзен

Чистого публичного API у Дзена нет. Автоматизация возможна только через
**импорт по RSS** (если он доступен для твоего канала в настройках Дзена) — тогда
можно отдавать ему RSS-ленту наших постов. Скажи, если нужно, — сгенерирую
`feed.xml` из истории и отдадим его через GitHub Pages.

## Рубрики (вечером, каждый день в 20:00)

Кроме утреннего поста есть **вечерняя рубрика в 20:00 каждый день** — и для всего
этого нужна всего **одна дополнительная рутина**. Она запускает навык-диспетчер
`rubric-today`, который сам определяет рубрику по дню недели и выполняет её:

| День | Рубрика | Навык |
|---|---|---|
| Пн | Документ / Дневник | `rubric-document` |
| Вт | Оружие / Техника | `rubric-weapon` |
| Ср | Двумя глазами | `rubric-perspectives` |
| Чт | Кадр недели | `rubric-photo` |
| Пт | В цифрах | `rubric-numbers` |
| Сб | Личность | `rubric-person` |
| Вс | Итог недели | `weekly-digest` |

Итого **3 рутины**, все на окружении **«WW2 Daily»** (токен, сеть, push в `main`
уже настроены — заново ничего не нужно):

| Рутина | Расписание | Промпт |
|---|---|---|
| Утренний пост | Daily · 09:00 МСК | «Запусти навык daily-post, следуя инструкции навыка. Работай автономно.» |
| Опрос-викторина | Daily · 15:00 МСК | «Запусти навык daily-poll, следуя инструкции навыка. Работай автономно.» |
| Вечерняя рубрика | Daily · 20:00 МСК | «Запусти навык rubric-today, следуя инструкции навыка. Работай автономно.» |

Календарь рубрик меняется в одном месте — `scripts/which_rubric.py`. Общая память
`state/history.json` обеспечивает антиповторы тем, фото (по `pageid`) и
личностей/техники (по `subject`) между всеми рубриками и утренним постом.

### Опрос (викторина, 15:00)

Опрос — quiz-режим Telegram (один верный ответ + пояснение) тем же ботом в тот же
канал. Память опросов — `state/polls.json`; навык избегает повторов тем и следит,
чтобы ответ был неочевидным (в т.ч. чтобы верный вариант не был самым длинным —
скрипт перемешивает порядок и предупреждает о перекосе длин).

Разовый импорт прошлой истории опросов из Airtable (CSV/TSV с колонками
`дата · вопрос · 4 варианта · индекс верного · пояснение`):
```bash
python scripts/import_polls.py --input polls_export.tsv   # по умолчанию TSV
```

## Структура

```
ww2daily/            пакет с логикой (даты, источники, Commons, Telegram, X, state)
scripts/             fetch_sources / find_photo / publish / fetch_week / which_rubric
                     + poll_context / publish_poll / import_polls
.claude/skills/      daily-post + daily-poll + rubric-today (диспетчер) + навыки рубрик
state/history.json   память постов (антиповторы тем, фото, личностей; поля kind/subject)
state/polls.json     память опросов (антиповторы вопросов/тем)
run/                 рабочие файлы запуска (в .gitignore)
```
