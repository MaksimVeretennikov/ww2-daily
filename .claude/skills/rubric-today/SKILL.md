# Вечерняя рубрика дня

Одна вечерняя рутина на все рубрики: по дню недели выбирается нужная и
выполняется. Работай автономно.

## Принцип дневника: без забеганий вперёд (важно для ВСЕХ рубрик)

Канал — дневник, который движется во времени. Целевая дата — сегодня минус 85
лет. **Всё в посте должно существовать и быть известно на эту дату:**
- не упоминай технику/оружие/модификации, появившиеся позже (пример: в 1941 —
  Т-34 обр. 1940/1941, но **не** Т-34-85, который появился в 1944);
- не раскрывай будущие события и исход войны как уже известные («позже стал
  маршалом», «в 1945…», итоговые потери за всю войну);
- цифры и факты — по состоянию на этот период, без послезнания;
- если к этой дате чего-то ещё не было — этого в посте нет.

Это правило применяй к той рубрике, которую выполняешь сегодня.

## Процедура

### Шаг 0. Подготовка
```bash
pip install -r requirements.txt
```
Подтяни полную память со всех веток, чтобы анти-повторы (темы, фото, личности/
техника) видели всё, что осело на ветках `claude/*` (см. README §8):
```bash
git fetch origin --prune
python scripts/consolidate_state.py
```

### Шаг 1. Узнать сегодняшнюю рубрику
```bash
python scripts/which_rubric.py
```
Команда выведет `rubric`, `skill` и `skill_path` для сегодняшнего дня (по
московскому времени). Расписание:

| День | Рубрика | Навык |
|---|---|---|
| Пн | Документ / Дневник | `rubric-document` |
| Вт | Оружие / Техника | `rubric-weapon` |
| Ср | Двумя глазами | `rubric-perspectives` |
| Чт | Кадр недели | `rubric-photo` |
| Пт | В цифрах | `rubric-numbers` |
| Сб | Личность | `rubric-person` |
| Вс | Итог недели | `weekly-digest` |

### Шаг 2. Выполнить рубрику
Открой файл навыка из `skill_path` инструментом **Read** и **выполни всю его
процедуру целиком** (сбор фактов → текст → фото → публикация → коммит памяти).
Все рубрики используют общие скрипты `fetch_sources.py` / `find_photo.py` /
`publish.py` и пишут в общую память `state/history.json` с правильным `kind`.

## Важно
- Запускается только одна рубрика за вечер — та, что выпала на сегодня.
- `publish.py` сам не выпустит вторую запись той же рубрики за день (защита от
  дублей). Если он так пишет — НЕ форсируй, просто заверши.
- Антиповторы (темы, фото по `pageid`, личности/техника по `subject`) работают
  через общую память автоматически.
- Викимедиа иногда отдаёт 429 на общий IP облачной сессии, и превью кандидата не
  скачивается (`local_path: null`). Это не повод отказываться от фото: выбирай
  по `title`/`description`, `publish.py` отдаст ссылку Telegram, и он скачает
  кадр сам. Если фото всё же не ушло, скрипт снимет строку-подпись к фото из
  текста — пост не должен начинаться с описания несуществующего кадра.
- Сохранение памяти делает сам навык рубрики (`git push origin HEAD:main`). Если
  вечерняя рутина на ветке `claude/*` и push в `main` не проходит — запись
  остаётся в ветке рутины и переносится в `main` следующей утренней
  консолидацией (см. README §8). Память не теряется.
