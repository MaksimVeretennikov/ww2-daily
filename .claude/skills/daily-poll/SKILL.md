# Ежедневный опрос (викторина)

Каждый день в 15:00 — один умный, **неочевидный** вопрос-викторина по Второй
мировой, привязанный ко времени, на котором сейчас канал. Работай автономно.

## Принцип дневника: без забеганий вперёд
Канал движется во времени. Целевая дата — сегодня минус 85 лет. Вопрос и все
варианты — **только о событиях/фактах, известных к этой дате** (с 1939 года до
целевой даты). Никакого послезнания и будущих событий.

## Процедура

### Шаг 0. Подготовка
```bash
pip install -r requirements.txt
```

### Шаг 1. Контекст
```bash
python scripts/poll_context.py
```
Прочитай `run/poll_context.json`: `date` (где сейчас канал), `events_today`,
`recent_posts` (о чём канал писал последние ~2 недели — можно зацепиться за тему
под новым углом), `recent_polls` (что **уже спрашивали — не повторяйся**).

**Обязательно просмотри `recent_polls` целиком** и особенно последний по дате
опрос. Прежде чем писать новый вопрос, держи в голове темы и формулировки всех
показанных опросов: новый вопрос не должен совпадать ни с одним из них по теме И
формулировке (та же тема под явно другим углом — допустимо, тот же вопрос —
нет). Если ничего по-настоящему нового по текущему периоду не придумывается —
смести фокус на другое событие/факт периода, а не переспрашивай вчерашнее.

### Шаг 2. Придумать вопрос
Сделай один вопрос:
- **интересный и неочевидный** — не «угадайка» из общих знаний;
- по периоду войны до целевой даты; можно связать с темой одного из недавних
  постов, но **под другим углом** (не дублируй сам пост);
- не повторяющий недавние опросы по теме И формулировке (та же тема, но другой
  вопрос — допустимо);
- с **одним однозначно верным** ответом и 3 правдоподобными дистракторами.

### Шаг 3. Записать `run/poll.json`
```json
{
  "ww2_date": "<date.iso>",
  "theme": "<кратко тема, по-английски, для антиповторов>",
  "question": "<= 300 символов (целься ≤ 280)>",
  "options": ["...", "...", "...", "..."],
  "correct_index": 2,
  "explanation": "<= 200 символов, почему верно именно это>"
}
```
- 4 варианта (минимум 3), каждый **≤ 100 символов**.
- `correct_index` — индекс верного среди `options` как написал (скрипт сам
  перемешает порядок, позиция верного будет случайной).

### Шаг 4. Опубликовать
```bash
python scripts/publish_poll.py
```

### Шаг 5. Сохранить память
`publish_poll.py` сам коммитит и пушит `state/polls.json` сразу после записи
опроса — отдельный коммит обычно не нужен. **Проверь его вывод:** если увидел
строку `Committed and pushed …` — память сохранена. Если вместо неё `WARNING:`
про неудавшийся push — закоммить и запушь вручную (иначе следующий запуск не
увидит этот опрос и повторит тему):
```bash
git add state/polls.json && git commit -m "poll: {theme} ({date.ru_human})" && git push origin HEAD:main
```

## Как сделать ответ НЕочевидным (важно)
Главный анти-паттерн прошлых опросов: **верным был самый длинный / самый
подробный вариант** — это выдавало ответ. Убираем это:
- **Все варианты примерно одной длины и стиля.** Верный ответ **не должен** быть
  самым длинным или самым детальным. Если он получился длиннее — сократи его или
  «догрузи» дистракторы до сопоставимой длины.
- Дистракторы — **реальные и правдоподобные** (настоящие операции/даты/имена того
  периода), а не абсурд. Хороший дистрактор — тот, что мог бы быть правдой.
- Не используй «всё перечисленное»/«ничего из перечисленного» и подсказки-маркеры
  («именно», «как известно»), выдающие ответ.
- Если `publish_poll.py` напишет WARNING про самый длинный вариант — перебалансируй
  длины и перезапиши `run/poll.json`.

## Прочее
- `publish_poll.py` не выпустит второй опрос за день (защита от дублей) — если так
  пишет, НЕ форсируй, просто заверши.
- Лимиты Telegram: вопрос ≤ 300, вариант ≤ 100, пояснение ≤ 200 — скрипт проверит
  и не даст превысить.
